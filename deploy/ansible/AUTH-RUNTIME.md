# Better Auth runtime provisioning

`codexia_stage=auth-runtime` is an explicit, non-activating prerequisite for a disposable Better Auth runtime. Set `codexia_auth_runtime_approved: true` only after reviewing its private control-node inputs. The stage verifies the canonical PostgreSQL container and the push deployment's shared `~/.local/state/codexia-deploy/host.lock`, then creates (or verifies) the `codexia_auth_runtime` login and the `codexia_auth` schema on the existing `codexia` database. It is an optional setup stage for an API configuration that consumes Better Auth, separate from first activation of the current token-authenticated API. **On a pristine database, complete the initial token-authenticated `deploy` before running `auth-runtime`.** Creating `codexia_auth` first would cause `initializeFreshPostgresSchema` to reject the non-pristine database. A compatible existing, fully initialized application migration ledger must already be present for this optional setup. It does not install or use an updater controller.

The role is restricted to login without superuser, role-creation, database-creation, replication, or RLS-bypass attributes. It has no membership in or grants to other roles, and the stage checks effective access to existing non-system schemas, tables, and sequences. The schema is owned by `codexia_auth_runtime`; the role gets no access to Core or public application tables. PostgreSQL's built-in `PUBLIC` defaults are left unchanged, so the stage does not revoke public schema usage or database temporary-object privileges from other roles. Runtime migrations must be run separately as this role after the schema has been provisioned.

Supply `codexia_auth_database_url_file`, `codexia_auth_secret_file`, `codexia_oidc_client_secret_file`, and `codexia_oauth_introspection_client_secret_file` as regular control-node files owned by the invoking identity and mode `0400` or `0600`. The URL must identify `codexia_auth_runtime` on `codexia-db:5432/codexia`, with no query or fragment. Use the same secret bytes for subsequent applies. The stage never rotates or replaces an existing Podman secret; it refuses mismatches. An initial partial secret set can be resumed only while the auth schema does not yet exist. Once a schema exists, every declared secret must exist and match before the stage continues.

Secret bytes are read with `no_log`, passed through standard input, and stored as rootless Podman secrets. They are never rendered into the nonsecret `~/.config/codexia-auth/runtime.env` file. The file contains only the validated `CODEXIA_*` origin, issuer, client ID, audience, and owner-subject settings. `codexia-api.better-auth.container.example` shows the corresponding environment-secret mapping but is deliberately not a loadable `.container` unit. `codexia_oauth_owner_subject` and `codexia_oauth_owner_client_ids` must identify an existing Better Auth user and the already registered public clients; this stage does not create either. The existing `adminCreateOAuthClient` API requires an authenticated Better Auth session and generates its client IDs. No approved first-session/client registration procedure exists for a token-only host yet, so staging inputs alone do not make activation ready.

This stage does not run migrations, install the example unit, restart or replace the API, or alter existing auth-token and PostgreSQL application secrets. The ordinary push `deploy` stage can run the candidate image's Better Auth migrations after its encrypted backup and verifies the owner and registered client records before activation. PostgreSQL backups capture database schemas and rows, but do not capture PostgreSQL roles or Podman secrets. Escrow the Better Auth secret values through the approved external secret authority; do not treat the existing restore drill as proof that auth credentials or schema ownership recover correctly. Initial owner/client registration, persisted-key continuity, isolated auth restore, reboot, rollback, and target-specific approval remain separate acceptance evidence before any production activation.
