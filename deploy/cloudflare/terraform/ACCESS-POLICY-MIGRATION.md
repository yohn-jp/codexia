# Shared Access policy migration

Supply `access_policy_id` for the existing account-owned reusable Allow policy. For ZENPRAX, use `7ea377b8-7f00-4273-9fba-dbc01bdabf21` (Allow-ZENPRAX team). Verify the policy's identity rules and inherited session duration before applying. Remove the old `allowed_emails` input from local tfvars and automation. Terraform 1.7+ is required for the non-destructive `removed` block. Back up state, run plan, and verify the old policy is forgotten without destruction and the application attaches the shared policy at precedence 1. Do not apply an older revision after the live migration. The CI compatibility application and its service-token policy are managed separately; preserve their precedence and scope. Delete the obsolete policy only after all application references are removed. Never import the shared policy into this module's ownership.
