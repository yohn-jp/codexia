# 試読ファイルと読者リンク

手元で校正したい場合はPublishingの書き出しを開き、形式と範囲を選ぶ。
期限付きで読んでもらいたい場合は、読み取り専用の読者リンクを選ぶ。
Desktop Webでは、作者向けのPublishingパネルから書き出しと読者リンクを操作する。iOSの画面は[SwiftUI設計](../architecture/IOS-SWIFTUI-ARCHITECTURE.md)に従う。

## 渡す前に確かめる内容

| 場面 | ファイルの書き出し | 読者用リンク |
| --- | --- | --- |
| 選ぶ | 確認する作品、巻または章、形式を選ぶ。EPUBでは表紙と図鑑付録の選択も確認する | 閲覧対象の巻、章またはシーンと、リンクの提案時から数える有効時間を選ぶ |
| 実行する | 選択範囲の保存済み本文をファイルにする。縦書きプレビューでは印刷やPDF保存に進める | 「リンク発行の提案を作成」でURLが表示される。作者が提案を承認して適用すると、期限内のリンクから閲覧できる |
| 終了する | ダウンロードの開始、プレビューの表示、印刷ダイアログを開く操作は別の状態として示す。配布先は作者が選ぶ | 一覧で取得時点の公開状態と期限を確認する。期限切れ、または失効の提案を承認して適用した後は、リンクから新たに開けなくなる |

すでに読者が手元に保存したコピーは、どちらの渡し方でも作者の画面から回収できない。
出力範囲の選択直後には作品・巻・章を確認でき、ファイル生成時には保存済み本文のみを対象にする。共有リンクは提案作成時点から有効時間を数え、承認・適用して「公開済み」を確認するまで読者には渡さない。

リンクは閲覧時点の保存済み本文を対象範囲から取得する。
同じリンクで参照できる本文は、その後に作品へ保存した変更に応じて変わる。

## 版や結果を確認できない場合

プレビュー後に本文や構成を更新した場合は、もう一度プレビューを開いて対象範囲を確かめる。
現行の書き出しは、プレビューと後続の生成操作の版が同じであることを保証しない。
版を固定した配布は、評価で必要性を確かめてから設計する。

対象章にシーンがなければ、本文のある章を選び直す。
縦書きプレビューの結果に本文がなければ、その場に空であることを示す。
リンク発行の応答が途切れた場合、画面でURLと発行結果を確認できるまでは配布しない。
既存の提案と共有リンク一覧で対象を確認する。
発行時だけ返るURLは、一覧から取得し直せない。

## 比較に使う作品と記録

作品「潮待ち」の第二章に最初のシーン「出港」と次のシーン「霧の中」を作る。
それぞれの一文を「汽笛が一度鳴った」と「灯台の光が消えた」とし、作者用ノートには「最終章で正体が判明する」と書く。
第三章には、第二章に含めない一文「明日の便で帰る」を置く。

手元で校正する課題では、第二章を選び、作者が予測した本文と章内の順を実際のファイルに照らす。
期限を定める課題では、第二章を対象にし、発行提案中、適用後、期限切れ、失効後の各段階で同じURLを読者側から確かめる。
ファイルと読者画面には第二章の二文だけが含まれ、作者用ノートと第三章を読めないことを確認する。
実行前に作者が選んだ渡し方、予測した本文、失効が効く範囲、迷った言葉を記録し、情報の優先順位を比較する。
