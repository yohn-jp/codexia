# Codexia — Desktop執筆環境の設計

## 位置付け

[情報設計](INFORMATION-ARCHITECTURE.md) と [UX contract](UX-CONTRACT.md) を具体化する再設計提案。React、CodeMirror、Radix、既存Workspaceと共通authoring coordinatorを維持する。

## 作業面の構成

通常の執筆は、幅を調整可能な構成ペイン、十分な本文領域、必要なときに呼び出す参照ペインからなる。これはWritingプリセットの初期配置であって固定3カラムではない。Research/Reviewプリセット、任意分割・tab・float・resize・非表示、レイアウト保存を維持する。既存のユーザー設定は読み込んだまま、明示的な操作だけで置き換える。

| 領域 | 役割 |
| --- | --- |
| 上部の静かな作業バー | 作品選択、現在の巻／章／シーン、保存状態と必要な操作。アカウント・テーマ・処理状況は補助 |
| 構成ペイン | 巻・章・シーン・ノートの展開可能な階層、現在位置、最近の作業、検索・作成 |
| 原稿ペイン | タイトル、本文、読み書き切替。原稿そのものに十分な幅と高さを割り当てる |
| 参照ペイン | 選択した語句やシーンに関連する知識、根拠、検索結果、必要な履歴 |
| 詳細状態 | 保護・保存・競合・ジョブ。重要な状態は通常の作業面から確認できる |

装飾より本文の読みやすさを優先する。横書き・縦書き閲覧、ルビ、和欧混植、長いシーン名、テーマの既存設定を保持する。本文の行長は組版設定で制御し、パネルのリサイズで意図せず文字サイズを変更しない。

## 操作の階層

- 作品切替は現在の作品名に結び付ける。新規作成、インポート、エクスポート、削除など頻度の低い操作は明示的なメニューやフォームを開いて行う。
- 構成は既存 parentId/orderKey/kind を用いた階層ツリー。親や数値の並び順を利用者が理解する必要はない。展開、追加、名称変更、移動、順序変更を対象行の操作として提示する。drag以外の手段を持ち、version precondition、循環防止、対象確認は既存APIを用いる。
- 執筆では、読む、保存、主要な書式操作を目立たせる。印刷、組版、履歴、Text Anchor、詳細な書式は文脈に沿った操作へ配置し、すべてを同時に並べない。選択範囲から根拠を作る操作は既存の確定Revision条件を満たすときだけ実行できる。
- パネルの移動・分割・サイズ変更は明示的な「レイアウト編集」から実行できる。通常の編集にパネル移動用のフォームが常に割り込まない。設定モードを閉じても本文とパネルは保持する。

## 保存と復帰

主表示は短く「下書き」「保存中」「保存済み」「要確認」を示し、詳細ではブラウザのjournal、対象Revision、現在の追加入力、DBの応答を区別する。「下書き」は同じブラウザに保護された場合のみ使用し、書込み失敗や照合中を成功扱いしない。保存中に追加入力があれば、その入力の状態を別に表示する。必要な競合・復旧判断には常時戻れる場所を用意する。

既存の再開候補から現在の作品・シーンを復元し、回復照合が終わるまでは編集可能に見せない。構成・検索・知識・レビューから原稿に戻るときは、可能な範囲で caret/selection/scroll/undo を復帰し、正規のguardを必ず通す。別シーンの選択と参照ペインの開閉を同一操作とみなさない。

## 検証

- 日本語長文、ルビ、複数巻・章・シーン、同名シーン、空の作品、長い名前で、作業対象と次の操作が見える。
- 構成変更の通常系、無効な移動、競合、キーボードによる順序変更が実際の永続化と一致する。
- IME変換中の通知・参照・パネル操作で入力を消失しない。保存中の追加入力、失敗、応答不明、再読込のjournal状態を観測する。
- Core/Full、標準とカスタム配置、狭いDesktop・200%拡大、ライト／ダーク、原寸／縮小で、本文が第一の視覚的重心である。
- 既存の表示設定、保存・復旧、履歴・組版、module contributionsと自由配置の回帰を既存ブラウザ受入で検証する。

## 代表レイアウトと寸法

基準は1440×900 CSS pxのDesktop。既存の可変splitを使い、初期状態の目安として以下を採用する。数値はレンダリングを見て調整でき、固定最小幅を全画面に強制しない。

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ codexia   作品名 ▾    第一巻 / 第一章 / 序章        保存済み   ⋯         │ 48
├──────┬─────────────────┬───────────────────────────────┬────────────────┤
│ 執筆 │ 構成       ＋ ⋯ │ 序章                     読む │ この原稿の参照 │
│ 知識 │ ▾ 第一巻         │                               │ 知識 / 根拠    │
│確認  │  ▾ 第一章        │   原稿本文                    │ 人物・場所     │
│      │    序章         │   日本語の行間と読み幅         │ 選択した引用   │
│      │    邂逅         │                               │ 関係           │
│      │  › 第二章        │                               │                │
│      │                 │                               │                │
│ 設定 │                 │                               │                │
├──────┴─────────────────┴───────────────────────────────┴────────────────┤
│ 作品・文書の補助情報    現在の本文文字数（計測できる場合）     接続詳細    │ 28
└─────────────────────────────────────────────────────────────────────────┘
```

初期の目安は rail 52px、構成240px、参照288px、残り約860pxを原稿領域。原稿の組版幅は既存のユーザー設定で制御し、周囲余白を差し引いた領域幅を超えない。構成と参照は各々閉じられる。1024px付近では参照を選択時に前面表示できるようにし、800px付近では構成を一時表示にするなど、実幅を優先する。既存の任意配置を保存済みの利用者には強制しない。狭幅での表示上の省略は永続layoutの破壊的変更ではない。

### 初期プリセットの具体案

| プリセット | 初期構成（利用可能なpanelのみ） | 重心 |
| --- | --- | --- |
| 執筆 / Writing | outline / editor / inspector、幅比約18:60:22 | 原稿 |
| 調査 / Research | outline / editor / inspectorと有効な検索・Story等を同一補助stack内で選択 | 原稿と参照 |
| レビュー / Review | editor / review（必要なinspectorを補助stackへ） | 差分と対象原稿 |

現行 `createWorkspacePreset` はeditorと補助stackの68:32 splitを生成する。本提案は初期構成を変更するものであり、layout schema/version、panel ID、保存key、浮遊panel、非表示panelを置換するものではない。`history` が登録されていない構成で無効な履歴railを置かず、WRT-02の実在する履歴導線を使う。Knowledgeの一覧・詳細はinspectorから利用できる。新panelが必要な場合もhostのcatalogと登録手順に従い、同じeditorの複数instanceを作らない。

### 画面部位ごとの操作仕様

| 部位 | 主操作 | 補助操作 | 表示しないもの |
| --- | --- | --- | --- |
| 作品名 | 作品切替・ライブラリ | 作成、取込、書出し | 常時展開された作成フォーム |
| 構成の行 | 展開／折畳、選択 | 追加、名称変更、移動、順序変更、削除 | 常時表示される親ID・orderKey |
| 原稿ヘッダー | タイトル、読む／書く、保存 | 組版、印刷、履歴、書式、scratch | 大きいDatabase workspaceタイトル |
| 原稿内選択 | 通常選択、copy、IME | 参照、根拠にする（確定Revision条件） | 勝手な選択確定・本文書換え |
| 参照 | 関連知識を開く、引用へ移動 | 関係・別名・命題詳細 | 常時展開された全登録フォーム |
| 状態 | 現在の保護状態、クリックで詳細 | 競合比較、照合、回復 | 状態を隠すための装飾 |
| パネル見出し | 対象名、閉じる／再表示 | 明示配置編集で移動・float等 | 通常時の常時表示移動フォーム |

### 構成ツリーの具体動作

構造はparentIdとorderKeyを元に組み立て、同名の巻・章・シーンでもstable document IDで選択する。深い階層はインデントと展開状態で表現する。親が欠落したデータを別作品へ接続せず、未配置として理由を示す。通常は選択中の祖先を展開する。選択中の行を折り畳む場合でも編集対象は変えない。

- 「追加」は親と文書kindを明示したフォームを開く。現在行の兄弟または子を明示選択し、既存createPersistenceDocumentのidempotency keyを保持する。
- 「移動」は対象と移動先を名前・階層で確認する。循環や許されない親候補は除外し、サーバーの検証を最終判断とする。
- 「上へ／下へ」は既存orderKeyとexpectedVersionによる一件の順序変更が表現できる時のみ可能。隣接キーの衝突、version不一致、複数更新が必要なケースでは成功を仮表示せず、最新構成の再取得と安全な操作を案内する。必要な原子的再順序化が現行APIにない場合は別途仕様化する。
- 「削除」は対象名、配下の影響、保持されるRevisionを説明し、明示確認と既存削除契約を通す。削除後は正規の返却データから選択し直す。未保存原稿の保護なしに削除・移動を強行しない。

ツリー項目の移動は、クリック可能な開閉と選択、行メニューを基本とする。ARIA treeを使うならarrow/Home/End、roving tabindex、expanded/selectedを一貫して実装する。dragは追加手段であり、既存データの安全な移動・順序変更が可能な範囲でのみ採用する。

### 執筆集中と配置編集

原稿の最大化は既存Workspaceのmaximize/restoreを利用する。集中表示からの復帰では元のsplit/active tabを再現し、永続設定を勝手に保存しない。レイアウト編集を開いたら移動元・先・配置方法とドラッグ可能領域を示し、閉じると通常の操作面に戻る。「配置を保存」は現行の明示保存と同じ意味とし、保存失敗・破損fallbackを明示する。原稿の「保存」と表示上も位置上も区別する。

### 責務の対応

`PersistenceWorkspace` のselectProject、selectDocument、protectTransition、saveDocument、editStructure、createAnchor、loadRevisions、restoreRevisionを通る。原稿のprojectionと保存処理をShellへ移さない。DesktopShellは主要導線と作業chrome、Workspaceはlayoutとpanel lifetimeを所有する。ManuscriptInputは編集・IME・undoの所有者であり、視覚刷新を理由に別editorへ置換しない。
