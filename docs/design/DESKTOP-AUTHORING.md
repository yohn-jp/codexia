# Codexia — Desktop執筆環境の設計

## 位置付け

[情報設計](INFORMATION-ARCHITECTURE.md) と [UX contract](UX-CONTRACT.md) を具体化する再設計提案。React、CodeMirror、Radix、既存Workspaceと共通authoring coordinatorを維持する。

## 作業面の構成

通常の執筆は、幅を調整可能な構成ペイン、十分な本文領域、必要なときに呼び出す参照ペインからなる。これはWritingプリセットの初期配置であって固定3カラムではない。Research/Reviewプリセット、任意分割・tab・float・resize・非表示、レイアウト保存を維持する。既存のユーザー設定は読み込んだまま、明示的な操作だけで置き換える。

| 領域 | 役割 |
| --- | --- |
| 上部の静かな作業バー | 作品選択、現在の巻／章／シーン、保存状態と必要な操作。アカウント・テーマ・処理状況は補助 |
| 構成ペイン | 巻・章・シーン・ノートの展開可能な階層、現在位置、最近の作業、検索・作成 |
| 原稿ペイン | タイトル、本文、読み書き切替。原稿そのものに十分な幅と高さを割り当てる |
| 参照ペイン | 選択した語句やシーンに関連する知識、根拠、検索結果、必要な履歴 |
| 詳細状態 | 保護・保存・競合・ジョブ。重要な状態は通常の作業面から確認できる |

装飾より本文の読みやすさを優先する。横書き・縦書き閲覧、ルビ、和欧混植、長いシーン名、テーマの既存設定を保持する。本文の行長は組版設定で制御し、パネルのリサイズで意図せず文字サイズを変更しない。

## 操作の階層

- 作品切替は現在の作品名に結び付ける。新規作成、インポート、エクスポート、削除など頻度の低い操作は明示的なメニューやフォームを開いて行う。
- 構成は既存 parentId/orderKey/kind を用いた階層ツリー。親や数値の並び順を利用者が理解する必要はない。展開、追加、名称変更、移動、順序変更を対象行の操作として提示する。drag以外の手段を持ち、version precondition、循環防止、対象確認は既存APIを用いる。
- 執筆では、読む、保存、主要な書式操作を目立たせる。印刷、組版、履歴、Text Anchor、詳細な書式は文脈に沿った操作へ配置し、すべてを同時に並べない。選択範囲から根拠を作る操作は既存の確定Revision条件を満たすときだけ実行できる。
- パネルの移動・分割・サイズ変更は明示的な「レイアウト編集」から実行できる。通常の編集にパネル移動用のフォームが常に割り込まない。設定モードを閉じても本文とパネルは保持する。

## 保存と復帰

主表示は短く「下書き」「保存中」「保存済み」「要確認」を示し、詳細ではブラウザのjournal、対象Revision、現在の追加入力、DBの応答を区別する。「下書き」は同じブラウザに保護された場合のみ使用し、書込み失敗や照合中を成功扱いしない。保存中に追加入力があれば、その入力の状態を別に表示する。必要な競合・復旧判断には常時戻れる場所を用意する。

既存の再開候補から現在の作品・シーンを復元し、回復照合が終わるまでは編集可能に見せない。構成・検索・知識・レビューから原稿に戻るときは、可能な範囲で caret/selection/scroll/undo を復帰し、正規のguardを必ず通す。別シーンの選択と参照ペインの開閉を同一操作とみなさない。

## 検証

- 日本語長文、ルビ、複数巻・章・シーン、同名シーン、空の作品、長い名前で、作業対象と次の操作が見える。
- 構成変更の通常系、無効な移動、競合、キーボードによる順序変更が実際の永続化と一致する。
- IME変換中の通知・参照・パネル操作で入力を消失しない。保存中の追加入力、失敗、応答不明、再読込のjournal状態を観測する。
- Core/Full、標準とカスタム配置、狭いDesktop・200%拡大、ライト／ダーク、原寸／縮小で、本文が第一の視覚的重心である。
- 既存の表示設定、保存・復旧、履歴・組版、module contributionsと自由配置の回帰を既存ブラウザ受入で検証する。
