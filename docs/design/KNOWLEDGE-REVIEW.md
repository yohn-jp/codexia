# Codexia — 知識管理と変更レビューの設計

## 位置付け

[情報設計](INFORMATION-ARCHITECTURE.md)、[UX contract](UX-CONTRACT.md)、[MCP-first](../architecture/MCP-FIRST.md) を具体化する再設計提案。Knowledge/EvidenceはCoreのPostgreSQL正本を使う。Storyの実体とKnowledgeのID対応、Native ChangeSet、module proposal、read/write set、version、receiptの責務を変更しない。

## 知識の三つの作業面

**一覧**は作品内の人物、場所、出来事、設定、用語を検索・絞込し、名前、型、状態、利用可能な根拠への導線を表示する。既存の型を表示し、未知の型も失わない。既存APIのページング／上限がある場合は取得範囲を明示し、読み込んだ部分集合を全体と偽らない。

**詳細**は選択した知識を主役とする。名前と状態、別名、属性、関係、根拠、命題を読みやすい順序で表示する。候補を確定する操作と新しい候補の登録を分離し、既存versionチェックと権限を維持する。Story entity IDの手入力は通常導線に置かず、既存Story実体から明示選択できる場合に限って選択UIを使う。同名一致による自動関連付けは禁止する。

**原稿参照**は現在のシーンや選択語句に紐づく知識だけを提示する。対象と根拠の対応を示し、一覧／詳細に移動しても元の本文位置へ戻る。本文未保存や古いRevisionの場合は現在の原稿に結び付いたと誤表示せず、確定済みRevisionへの参照と現入力を区別する。

## 関係の可視化

関係一覧を基準に、必要な範囲だけを局所グラフに投影する。グラフを新たな正本にしない。ノードはstable ID、エッジは既存関係の方向・型・状態・有効範囲で結び、候補／確定／退役を区別する。対象のないエッジ、未ロードの関係、曖昧な別名から事実を推定しない。グラフがない場合も関係一覧で全操作に到達できる。

グラフでは選択ノード周辺の関係を表示し、詳細を開く。全作品の無制限なグラフ描画、距離や中心性に意味を付与すること、ドラッグによる暗黙の関係変更は必須としない。グラフ用ライブラリの採用やサーバーAPIの追加は、既存のprojectionで達成できないことが確認された場合に別途判断する。

## 根拠と視点

引用は原稿の出典、該当Revision、アンカーの状態、リンクの状態を表示する。現在本文と一致するなら該当位置へ移動し、古いRevision・要確認・孤立の場合はその理由と正規の復旧／比較導線を提示する。推測で新しい引用位置を確定しない。

事実、人物の認識、読者への開示、仮説を別の意味として表示する。作者向けの全知識を読者や登場人物の視点に無条件で流用しない。Storyのscope/perspective/snapshotの境界を利用し、利用者が指定した視点と範囲を常に示す。全情報を参照できる作者の画面であっても、作者の確定していない候補を正本の事実として表示しない。

## 変更レビュー

一覧では提案の対象作品、主な対象、由来、状態、変更件数、確認すべき影響を提示する。詳細では対象の名前、変更前後、関係・根拠の追加変更、引用元を読める形で表示する。未知の操作は成功したように要約せず、既存の詳細情報と確認不能の表示を用意する。read/write set、version、operation ID、receiptは技術詳細として展開できる。

| 状態 | 許される操作と表示 |
| --- | --- |
| 提案中 | 内容確認、承認、却下。未適用の正本には反映しない |
| 承認済み | 対象の再確認、既存APIによる明示的な適用。承認だけで成功表示しない |
| 適用済み | receipt、反映対象、更新後の正本を確認する |
| stale／競合／応答不明 | 元のversionと状態を再確認し、利用可能な正規操作だけを提供する |
| 却下／退役 | 通常の正本表示から区別して履歴を保持する |

Native ChangeSetとmodule proposalの権限・原子性・操作単位を変えず、それぞれの正規詳細から処理する。部分承認など既存のAPIが保証しない操作をUIで作らない。Knowledgeの統合は既存previewDigest、projectVersion、明示確認、競合検証を通し、参照移行と統合元退役の意味を提示する。

## 受入

- 原稿から知識、知識から根拠の該当箇所へ戻れる。古い根拠、同名ノード、複数別名、未確定関係、仮説が混同されない。
- ノード・関係・別名・命題の既存候補／確定／却下／退役操作、統合previewと適用結果を失わない。
- グラフと一覧は同じ正規ID、状態、範囲を表示し、視点・snapshot・取得上限を越えない。
- MCPの提案を承認しただけでは正本が変わらず、明示適用後のreceiptと正本が一致する。stale/replay/cross-project/未認可の否定系を維持する。
- Coreでもnative Knowledge/Evidence/ChangeSetを利用できる。任意moduleや外部LLMへの依存を追加しない。
