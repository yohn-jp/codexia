# Backend handoff revalidation

The **Revalidate Backend Deployment Certificate** workflow is a read-only recheck of an already published backend release. It uses only the workflow's short-lived read-scoped `GITHUB_TOKEN`; it has no deployment credentials. Run it manually from `main` with a successful `Codexia Backend Image` run ID. The run is looked up through GitHub's authenticated API, constrained to the canonical workflow, repository, main branch, successful conclusion and exact run attempt. The workflow then checks out the run's source commit and invokes the verifier from the current `main` checkout against that source-bound event.

The verifier checks the publisher artifact, the Core and Full certificates, the source verification and producer receipt, release records, and the immutable OCI image identities. The job has only read permissions for repository contents, workflow artifacts and packages. It has no environment, deployment identity, SSH key, host connection or production write permission. It records `NOT_ESTABLISHED` for target-specific recovery; a successful certificate check is not a deployment approval.

The existing candidate publisher run is `44878012473`, from main source `94d7cb890fa7c61fc03b6f5153893a8acc9f9609`. Its publication succeeded, while the original handoff run failed on GitHub's skipped matrix-job representation. The merged #462 verifier change accepts that exact promoted-run representation while retaining the complete main-build fallback. Revalidating this run after this workflow is integrated can establish the certified image handoff; it cannot establish access or recovery for the production target.

This workflow does not implement the separate disposable push convergence and rollback fixture. The existing #443 host bootstrap and #444 isolated backup/restore results remain historical fixture evidence, and reboot recovery remains outside this check. None of these fixture results prove production-host readiness.
