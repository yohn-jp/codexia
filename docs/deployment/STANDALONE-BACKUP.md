# Standalone backup and isolated restore drill
 
This is an operator-invoked O3 maintenance tool, distinct from portable work JSON. Run as the rootless Podman deployment user with the same updater state directory. Requires Podman, age, flock, GNU coreutils, findmnt, the existing pinned PostgreSQL 17 image, and a remote mounted NFS/CIFS/SSHFS destination. Provision the age recipient and recovery identity independently; never store the private key on the source VM or alongside the backup. The destination must be independently protected against deletion and have a retention policy.
 
## Backup
 
1. Pause the updater and stop its timer. Block proxy admission and stop the active API, all preflight containers, and any other database/history writers. Confirm database connectivity and that no external administrative writes are occurring. Leave PostgreSQL running. The script holds the same host flock, refuses a live known writer, and verifies the blocked route. It does not stop production services itself.
2. Run bash deploy/updater/standalone-backup.sh backup /absolute/remote/mount age1-public-recipient. The destination must resolve to a remote filesystem. The database custom-format dump and history volume archive are streamed directly into age ciphertext. The encrypted manifest contains logical fingerprints of all public database tables and history file contents. Repeated fingerprints detect unexpected changes during capture. Ciphertext checksums are recorded; a partial directory is renamed only after all files have been written and synchronized.
3. Resume the journaled writer through the boot command, check its routed readiness, then resume polling. Record backup timestamp, remote location, ciphertext checksum verification, and recovery-key custody. Off-site replication and retention are operator infrastructure responsibilities.
 
## Restore drill
 
Run bash deploy/updater/standalone-backup.sh drill /absolute/backup/directory /private/age-identity from an isolated recovery machine with Podman. The script validates fixed ciphertext checksums, decrypts the manifest, creates uniquely named disposable PostgreSQL and history volumes, and restores without a network or published port. It compares all public-table contents and history file hashes against the backup manifest. It never restores to the live database or history volume. The scratch containers and volumes are deleted on exit.
 
The restore drill does not restore production role passwords, grants, Cloudflare credentials, systemd configuration, or browser-local drafts. Reprovision those through existing operational contracts. The logical fingerprint covers row values, not physical WAL, sequence state, ACLs, or server settings; pg_restore additionally restores schema and sequence definitions. The history fingerprint covers regular file names and contents, not filesystem metadata. Do not claim a complete disaster-recovery acceptance until actual recovered API startup, login, document revision, Knowledge, Evidence and approval workflows have been checked. Run recovery drills with real encrypted off-VM backup artifacts and document measured RPO/RTO. No target VM was touched by this PR.
